## 停止服务后恢复操作修复

用户实机反馈停止服务后 Get-SmbServerConfiguration 返回 Windows System Error 111，原先整块概览读取失败并锁定启动按钮。现改为先读取服务状态；服务未运行时跳过协议配置查询，运行时协议查询失败仅返回 configurationError。界面显示协议状态未检测，保留真实服务状态及启动入口，不将缺失配置显示为已关闭或无签名要求。共享查询失败仍与服务操作隔离。

PowerShell CLIXML 错误解码为可读文字，保留错误原因。新增测试完全替换 Get-Service 和 Get-SmbServerConfiguration，覆盖停止时跳过配置、运行时配置失败以及正常配置；新增模拟界面测试验证停止后共享读取失败仍可启动，再次启动后状态恢复。真实服务启停未在此次回归中执行，用户提供的实机错误是问题线索，不代表修复后实机验证完成。

## SMB TCP 端口能力纠正

用户实机反馈端口修改不生效。旧 changeSMBPort 实现写入 LanmanServer\Parameters\SmbPort 再重启服务，并不能提供有效的 Windows SMB TCP 端口修改功能，已移除。SMB 的 canChangePort 现为 false；界面仅查看并说明 TCP 445 不支持直接修改；后端在权限检查和任何命令执行前明确拒绝 LanmanServer 修改请求。不会为此次纠正重启服务，也不会自动清理用户机器上之前可能写入的注册表值。

依据：[微软 SMB 替代端口文档](https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-ports)。文档区分客户端连接替代端口与服务端监听能力；Windows 服务端支持修改 QUIC 监听端口，当前 TCP 页面未实现 QUIC 管理。

新增后端拒绝测试与浏览器 SMB 行只读测试；保留 RDP、WinRM 支持范围及原有检测算法。此次纠正替代此前“SMB 端口实际效果未验收”的表述，该 TCP 修改入口已确认为不支持，而非待验收功能。

## 同名规则兼容性修复

Windows 允许多个规则拥有相同 DisplayName。旧实现仅以显示名称和方向判断唯一目标，导致可以新增同名规则却无法编辑；禁止新增重名并非最终方案，本轮保持 Windows 的重名能力。

GetRules 改为固定 PowerShell 结构化查询，读取 Name 为 id、DisplayName 为 name，并按内部实例关联地址、端口和应用过滤器。编辑、删除和启停通过内部 ID 定位，复核原名称/方向及唯一可编辑本地对象；缺少 ID、ID 歧义、目标已变化或只读策略仍拒绝。表格行键与编辑表单保留 ID；查询保留原 ICMP 类型元字段，协议未变时不重置过滤条件。

旧版报告中“同名即拒绝”的描述已被本节替代。新增模拟测试确认两条同名不同 ID 规则可以单独编辑、启停和删除；另测试缺失/歧义 ID 拒绝。Go 测试、静态检查、30 项前端单元测试及 28 项界面测试通过，Wails 绑定重新生成。

本轮做了只读 Windows 采样，确认一条规则的 Name/InstanceID 与端口过滤器 InstanceID 对应，Get-NetFirewallPortFilter 支持 PolicyStore 参数。但当前工具进程完整读取过滤器被 Windows 拒绝，尚未完成真实管理员全量查询及写操作验收。管理员应用中查询耗时和同名规则实际操作需用户按更新后的 F4 验证。未新增、编辑、启停或删除任何真实规则，未提交或发布。
